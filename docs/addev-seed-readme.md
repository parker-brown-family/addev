# ADDev

**Agentic Delight Development Environment.** An agentic development environment
for one person, built into Omarchy.

MIT licensed. Part of the `*-delight` family, alongside
[terminal-delight](https://github.com/parker-brown-family/terminal-delight),
markdown-delight and context-delight.

> **Status: seed.** Nothing is built. This repository exists to hold the shape of
> the idea and its constraints. See `docs/vision.md`.

## What it is

You run coding agents. They produce more work than you can look at, and nothing
on Linux helps you decide what deserves your attention next — the tools that
try are macOS-first, team-shaped, and route your code through someone else's
cloud.

ADDev is the version of that for a person working alone on their own machine.
Local only. No account, no server, no telemetry leaving the box.

## What it is not

**Not a free tier of something.** There is a commercial product in this space
from the same people, aimed at large teams on established codebases. ADDev is not
that product with features removed, and it is not a funnel into it.

The two are built for opposite economics. Running several agents at one task is
cheap on a small codebase and expensive on a large one; a solo developer wants
speed and low ceremony where a large team wants audit, review gates and
provenance. Those pull in different directions, and a single codebase serving
both serves neither. So this is a different program for a different person, and
it stays that way.

**Not a generic Linux tool.** Omarchy is the target. Installable in one command,
themed with the system, bound to its keys, at home there rather than ported to
it. Portability to other Linux desktops is welcome later and is not a design
constraint now.

## Why Omarchy

An agentic environment competing everywhere competes with everyone. One built for
a specific, opinionated, actively-used desktop has a community, a coherent set of
conventions to adopt rather than invent, and no incumbent.

It also matches how the rest of the family is built: read the operating system
you are actually on, and take its conventions instead of inventing parallel ones.
